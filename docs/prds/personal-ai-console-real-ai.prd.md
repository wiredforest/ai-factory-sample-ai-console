## 1. なぜ今か

- フェーズ 1〜4 で、偽の応答役を相手にした会話・履歴・状態は揃った。一方で、本物の AI (`CONSOLE_LLM=anthropic`) への接続は、工場が本物の AI を呼ばない (MISSION 不変条件 4) ため、応答が途中で切れた場合・AI が回答を断った場合・鍵の誤りや混雑の場合を、まだ誰も扱っていない。今はどの失敗も「AI に繋がりません」の 1 つにまとめられ、切れた応答はそのまま完成した応答のように表示される
- 元の PRD で先送りにした Web Search を、DEN さんが足し方を決めた (2026-11-24)。Messages API の web search ツールを有効にするだけにし、MCP は使わない

## 2. 実装フェーズとユーザーストーリー

### フェーズ 5 — 本物の AI と Web Search

- **S13 本物の AI の応答を、誤解なく受け取る**: DEN さんとして、本物の AI の応答が途中で切れたり、回答を断られたり、届かなかったりしたとき、何が起きたかを画面で知りたい。切れた応答を完成したものと思い込まないように
  - 受け入れ条件: 応答が長さの上限で途中で切れたとき (`stop_reason` が `max_tokens`) は、届いた分を表示し、途中で切れたことが分かる一文を添える。届いた分とその一文は、AI の応答として記録され、会話を開き直しても見える
  - 受け入れ条件: AI が回答を断ったとき (`stop_reason` が `refusal`) は、断られたことが分かる一文を表示する (届いた分があればその後に添える)。これも AI の応答として記録される
  - 受け入れ条件: 送信が失敗したときは、理由を見分けて表示する。少なくとも「鍵が正しくない (401・403)」「混んでいる。少し待って送り直す (429・529)」「AI に届かない (通信の失敗・待ち時間切れ・そのほか)」を区別する。どの場合も、今と同じく何も記録せず、送った本文は失わない。表示にも記録にもログにも、鍵の文字列を出さない
  - 受け入れ条件: 検索の途中で止まった応答 (`stop_reason` が `pause_turn`) を、完成した応答として黙って表示しない。続きを取りに行って完成させるか、完成しなかったことが分かる表示にする
- **S14 AI が Web を検索して答え、出典が分かる**: DEN さんとして、最近の出来事や調べものを尋ねたとき、AI に Web を検索して答えてほしい。答えの裏付けを自分で確かめられるように
  - 受け入れ条件: 本物の AI に送るとき、Messages API の web search ツールを有効にする。検索するかどうかは AI が決め、1 回の応答で検索するのは最大 3 回まで
  - 受け入れ条件: 検索を使った応答では、応答の本文の後に、出典の URL (と分かれば題名) が並ぶ。同じ URL は 1 回だけ並べる。出典は応答の本文の一部として記録され、会話を開き直しても見え、続きを送るときも前のやり取りとして AI に渡る。記録の形 (テーブルや列) は変えない
  - 受け入れ条件: 検索を使わなかった応答は、今と同じ形のまま (出典の欄を空で付け足さない)
  - 受け入れ条件: 検索が失敗したとき (検索の結果がエラーだったとき) も、AI の応答が届けばそれを表示する。検索できなかったことを応答の本文が伝えない場合は、検索できなかったことが分かる一文を添える
- **S15 モデルを環境変数で選ぶ**: DEN さんとして、調べものの重さに合わせて、起動するときにモデルを選びたい。普段は安いモデルで、難しい相談のときだけ賢いモデルを使えるように
  - 受け入れ条件: 環境変数 `CONSOLE_MODEL` でモデルを選べる。未設定なら `claude-haiku-5-5`。変えたらアプリを再起動して反映する (再起動しても会話の記録は残り、過去の会話の続きも新しいモデルで話せる)
  - 受け入れ条件: その環境変数を読む箇所の近くに、サンプル値 (`claude-haiku-5-5`・`claude-sonnet-5-5`・`claude-opus-5-5`) と、それぞれを選んだときの効果 (速さ・賢さ・料金の目安・検索の違い) を、日本語のコメントで残す
  - 受け入れ条件: web search ツールの版は、選んだモデルから自動で決まる。Sonnet 5.5・Opus 5.5 などの対応するモデルでは、検索結果を絞り込む版 (`web_search_20260209`) を、それ以外 (Haiku 5.5 など) では基本の版 (`web_search_20250305`) を使う。利用者が検索の版を設定する必要は無い
  - 受け入れ条件: モデルの名前を打ち間違えたときは、送る前に分かる。サーバの状態のメニューの「AI への接続」は、そのモデルの情報を取得する方法 (`GET /v1/models/<モデル名>`、トークンを使わない) で確かめ、取得できなければ「異常」にする
  - 受け入れ条件: 偽の応答役 (`fake`・`fake-down`) では `CONSOLE_MODEL` を使わず、値が何であっても今と同じに動く

## 3. 確かめ方

- 工場は本物の AI を呼ばない (MISSION 不変条件 4)。S13〜S15 の、本物の AI との受け答えに関わる受け入れ条件は、Messages API の応答の形 (検索の結果と出典を含む応答、`max_tokens`・`refusal`・`pause_turn` の応答、401・403・429・529 と通信の失敗) を固定のデータにしたユニットテストで確かめる。このとき、送るリクエストの中身 (モデル、ツールの版、`max_uses`、system prompt、それまでのやり取り) もテストで確かめる
- 偽の応答役の応答文 (`fake reply #<n>: <直前の発言>`) は変えない。画面での確かめ (ゲート 3) は、今までどおり偽の応答役で行う
- 本物の鍵での確かめは、DEN さんが手元で行う

## 4. Non-goals

- 画面での検索のオン・オフ、画面でのモデルの切り替え
- web search 以外のツール (web fetch、コードの実行、MCP など) を AI に持たせること
- 検索するサイトの制限 (`allowed_domains`・`blocked_domains`)
- 応答を少しずつ流して表示すること (MISSION のスコープ外のまま)
- 検索の回数やトークン・料金の集計 (MISSION のスコープ外のまま)
