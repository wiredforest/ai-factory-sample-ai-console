> **対になる PRD**: [personal-ai-console.prd.md](personal-ai-console.prd.md)。PRD が「何を・なぜ」、本書が「どう取り組むか」を持つ。タスクごとの実装計画は持たない (それは工場の ticket と plan の領分)。

## 問題と目標

DEN さんが手元で、AI と短く対話し、過去の会話を開き直し、サーバの状態を確かめられる、自分専用の会話コンソールを作る。本当の目的は、ai-factory 研究の段階 1 で、工場にこのアプリを作らせて最初の 1 周を見届けること。だから以下の判断はすべて、**工場がこのアプリを起動して外から確かめられること**と、**軽く動けば足りること** (DEN さん) を物差しにする。

## 第一原理 — 工場がアプリを動かす条件

工場のランタイムホスト (見本の `template/factory/RUNTIME_HOST.md`) は、アプリを自分で起動して外から確かめる。そのための条件が、スタックの選び方を決める。

| 条件 | アプリへの帰結 |
| :--- | :--- |
| 起動 (`command`) とセットアップ (`setup`) に書けるのは、Python か Node の引数の並び (`{python}` `{source}` `{state}` `{port}` を置換) だけ。シェル、バッチ、プロバイダーの CLI は失敗する | 依存パッケージを入れるなら、Python のスクリプトで検証用の写しの中に毎回入れることになる |
| 写しに含まれるのは、設定で指定したファイルとディレクトリだけ。仮想環境・`.env`・`.git`・`.claude` などは指定できない | 手元の `.venv` は使われない |
| アプリに渡すのは最小限の OS 環境と、設定に書いた `env` だけ。プロバイダーの認証情報は渡さない。HOME と一時ディレクトリは新しい状態ディレクトリを指す | **工場の検証では本物の AI を呼べない**。決まった応答を返す偽の応答役が必須 |
| 書き込む DB とアプリのデータは、すべて `{state}` (または `FACTORY_RUNTIME_STATE`) に置く | DB のパスを環境変数で受け取る |
| HTTP のアプリは、ヘルスチェック (`/health`) と、`FACTORY_RUNTIME_CANDIDATE` の文字列をそのまま返す同一性確認 (`/build-id`) を、リダイレクトなしの 200 で返す | 2 つのエンドポイントが要る |
| 工場のハーネスは、静的検査とユニットテストのコマンドを、シェルを介さずに `shlex.split` で実行する (`template/harness/ci.py`) | `uv run …` のように、PATH 上の実行ファイルから始まるコマンドなら書ける |

## 検討したアプローチ

| 案 | 中身 | 良い点 | 弱い点 |
| :--- | :--- | :--- | :--- |
| **A. 標準ライブラリだけで動かす (採用)** | `http.server` + `sqlite3` + `urllib` で Anthropic の API を直接呼ぶ。画面は静的な HTML と素の JS が 1 枚。テストと lint だけを uv で管理する | 動かすのに入れるものが無く、工場の起動条件にそのまま乗る。「Python を基本とする最小のパッケージ構成」を最も満たす。見本 (ai-software-factory) 自身も標準ライブラリだけで書かれている | ルーティングや JSON の受け渡しを手で書く分、コードが少し増える。SDK を使わない |
| B. FastAPI + uvicorn + Anthropic SDK | 一般的な構成 | 書く量が少ない。よく知られている | 工場の検証のたびに、Python のスクリプトで依存を入れる手間がかかる。ネットワークと時間に左右される |
| C. Streamlit などの Python 製 UI | 画面まで Python で書く | 画面を早く作れる | WebSocket で動くため、HTTP で外から確かめる工場の検査と相性が悪い。依存も重い |

**A を採る** (DEN さん、2026-11-22: 「今回はアプリ自体は軽く動けば良いので A で良い」)。

## 推奨アプローチ

標準ライブラリだけで動く、1 プロセスの小さな HTTP アプリ。ブラウザには静的な HTML と素の JS の 1 枚を返し、画面はそこから JSON の API を呼ぶ。会話の記録は SQLite に置く。AI は Anthropic の Messages API を `urllib` で呼び、環境変数で偽の応答役に切り替えられる。工場の検証・テスト・CI はすべて偽の応答役で動かし、DEN さんが手元で使うときだけ本物の AI を呼ぶ。

コードは垂直スライスで、機能 (会話・履歴・サーバの状態) ごとに、受け口・処理・データの読み書き・テストを 1 か所にまとめる。

## 主要な判断

### スタックとライブラリ

| 対象 | 決定 | 理由 / 代替 |
| :--- | :--- | :--- |
| 言語と実行時 | Python 3.14、標準ライブラリだけ (実行時の依存パッケージは 0) | 工場の起動条件に乗る。代替は B・C (上の表) |
| HTTP サーバ | `http.server` (`ThreadingHTTPServer`) | 1 人で使う小さなアプリには足りる |
| 画面 | 静的な HTML・CSS・素の JS が 1 枚。サーバからは JSON を返す | 外から HTTP で確かめやすい (JSON の API を直接叩ける)。ビルドの道具が要らない |
| 会話の記録 | `sqlite3` | DEN さんの指定 (2026-11-22) |
| AI | Anthropic Messages API を `urllib` で直接呼ぶ。model は既定で Claude Haiku 5.5 (`claude-haiku-5-5`)。`CONSOLE_MODEL` で選べる (2026-11-24) | 速く、安い。将来の Web Search も同じ API のツールとして足せる。SDK は依存になるので使わない |
| 開発の道具 | uv で、pytest と ruff を開発用の依存として管理する | 実行時には使わない。工場のハーネスからは `uv run …` で呼べる |

### データモデル

- **会話**: 会話 1 件。作成時刻・更新時刻を持つ。履歴の一覧は更新の新しい順
- **メッセージ**: 1 つの会話に複数ぶら下がる。話者 (人 / AI)・本文・時刻を持つ
- 置き場は SQLite の 1 ファイル。パスは環境変数で受け取る (工場の検証では `{state}` の下)
- 会話を見分ける手掛かり (PRD S7 の未解決の問い) は、モデルに専用の項目を足さずに、最初のメッセージなどから表示で作れる形にしておく。決めるのは ticket の段階

### 境界と契約

- **待ち受け**: `127.0.0.1` だけ。認証は設けない (使うのは 1 人。PRD の作らないもの)
- **鍵**: `ANTHROPIC_API_KEY` を環境変数から読むだけ。repo は GitHub で public なので、鍵を repo に置かない (`.env` は git に無視させる)。鍵が無いときは、サーバの状態で「AI への接続」が異常になる
- **偽の応答役**: 環境変数で切り替える。直前の発言と、それまでの往復の数を入れた、決まった応答を返す。これで PRD の S3 (応答が出る) と S5 (前のやり取りを踏まえる) を、毎回同じ結果で確かめられる。工場の検証・テスト・CI は偽の応答役で動かす
- **工場との契約**: `/health` (アプリ自身が動いているか) と `/build-id` (`FACTORY_RUNTIME_CANDIDATE` をそのまま返す) を、リダイレクトなしの 200 で返す。DB のパスと AI の切り替えは環境変数で受け取る
- **サーバの状態 (PRD S2)**: アプリ自身は `/health`、会話の記録は実際に読めるか、AI は本物ならモデルの一覧を取る API (トークンを使わない) で確かめる。偽の応答役のときは AI を常に正常とする
- **外部サービス**: Anthropic の API だけ。プロンプトインジェクションへの強い対策は設けない (PRD の作らないもの)

### その他

- **構成**: 垂直スライス (`reference/architecture_patterns.md` のパターン 1)。機能のフォルダは `chat` (会話)・`history` (履歴と再開)・`status` (サーバの状態) の 3 つ。共有するものは `db`・`llm` (本物と偽の応答役)・`config` だけにし、スライスどうしは直接呼び合わない
- **応答の表示**: 全文が揃ってから返す (PRD の作らないもの: 少しずつ流す表示)。ストリーミングの仕組みは作らない

## 不足している要素

- 偽の応答役 (本物の AI と同じ受け口で、決まった応答を返す)
- 工場のランタイムホストの設定 (`include`・`command`・`env`・`health_path`・`identity_path`)。工場の据え付けのときに、セットアップの agent が書く
- CI (GitHub Actions)。最初の ticket で揃う見込み (README の手順 5)
- 会話の記録の表 (最初に使うときに作る)
