# ファクトリーをアップグレードする

インストール済みのファクトリーをアップグレードするには、ファクトリーのリポジトリで変更を pull し、
アプリケーションのリポジトリから `python <factory>/bin/factory.py init` を再実行します。

- `init` は `template/` 内のファイルと、`factory/pack.json` でリビジョンを固定した Archon のソースをインストールし、そのソースを検証します。
- プロジェクト用に自分で記述するファイルは上書きされません。`MISSION.md`、`harness/END-TO-END.md`、
  `harness/harness.config.json`、`.factory/holdout/HOLDOUT.md` のほか、インストーラーに列挙されたプロジェクト用ファイルが該当します。
- インストール後に変更したファクトリーのファイルは、新版で置き換える前に `.factory/backup/` にコピーされます。
  アップグレードを繰り返した場合は、コピーに連番が付きます。
- アップグレード後に `python factory/consumer.py doctor` を実行してください。固定したリビジョンのソースを点検し、すべての共有ワークフローが検証に通ることを確認します。

ファクトリーと Archon の担当範囲は次のとおりです。

- **Archon** はすべてのワークフローとエージェントを管理します。トリアージ、デリバリー、レビュー、検証、ランタイム検証とホールドアウト検証、修復、発見事項の処理、マージ、デプロイ、ネイティブトリガーによるスケジュール実行を担います。
- **ファクトリー** は、プロジェクトのコンテキストファイル、インストール、Archon を呼び出して状態を表示する薄いクライアントを管理します。
- **ランタイムシナリオ** はプロジェクト側で用意する入力です。検証対象の候補を実際に起動した新しい環境で、その動作を確かめる必要があります。

ファクトリーを定期実行している場合は、アップグレード後に `python factory/consumer.py schedule install` を再実行してください。
これで、追加された入力がトリガーのバインディングに反映されます。
